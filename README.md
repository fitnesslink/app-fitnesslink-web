# FitnessLink Web

Consumer-facing web app for FitnessLink. Mirrors the iOS and Android apps on mobile; takes cues from the [fitness-management](../fitness-management) admin app on desktop.

See [PLAN.md](PLAN.md) (Phases 1–5: auth, plans, payment, onboarding) and [PLAN_MAIN_APP.md](PLAN_MAIN_APP.md) (Phases 6–15: main app port) for scope and architecture.

---

## Getting started

1. Install deps: `npm install`
2. Copy env template: `cp .env.example .env.local` and fill in:
   - `NEXT_PUBLIC_FIREBASE_*` from [fl-appmanager/src/firebase/firebase.ts](../fl-appmanager/src/firebase/firebase.ts) (shared config across every FitnessLink client)
   - `FIREBASE_ADMIN_*` from a service-account JSON (Firebase Console → Project Settings → Service Accounts → Generate new private key)
3. Start the platform API in another terminal: `cd ../fitnesslink-platform && docker-compose up` (listens on port 5100)
4. `npm run dev`

## API types — regeneration workflow

All API request/response shapes come from the platform's OpenAPI spec — we never hand-write DTOs.

- `openapi.snapshot.json` — committed snapshot of the spec. Source of truth for generated types in CI.
- `src/types/api.ts` — generated by [`openapi-typescript`](https://openapi-ts.dev). **Do not edit by hand.**

### Regenerating after an API change

With the platform API running on `http://localhost:5100`:

```sh
npm run gen:api
```

This fetches `http://localhost:5100/swagger/v1/swagger.json`, rewrites `openapi.snapshot.json`, and regenerates `src/types/api.ts`. Commit both files together.

Override the fetch URL if needed:

```sh
OPENAPI_URL=https://staging.example.com/swagger/v1/swagger.json npm run gen:api
```

### Checking in CI

```sh
npm run gen:api:check
```

Regenerates types from the committed `openapi.snapshot.json` and fails if the result differs from `src/types/api.ts`. This is wired into [`.github/workflows/ci.yml`](.github/workflows/ci.yml) — drift between the snapshot and generated types blocks merge.

### API client modules

Per-controller client modules live in `src/lib/api/{core,nutrition,notifications,billing}/` — one file per platform controller, each exporting named functions + a `keys` Query-key factory. These are **auto-generated** from the spec snapshot too:

```sh
npm run gen:api:clients
```

Every file starts with an `AUTO-GENERATED` banner. Don't hand-edit them; rerun the generator after the snapshot changes. If a generated function name reads awkwardly, refine the heuristic in [`scripts/gen-api-clients.mjs`](scripts/gen-api-clients.mjs) and regenerate.

Usage example:

```ts
import { workouts } from "@/lib/api/core";
import { useQuery } from "@tanstack/react-query";

function WorkoutsList() {
  const { data } = useQuery({
    queryKey: workouts.keys.lists(),
    queryFn: () => workouts.listWorkouts(),
  });
  // …
}
```
